# Сервис заказов

Создание, чтение, отмена и список заказов с пагинацией и фильтром по статусу. Контракт операций описан через swaggo и доступен в Swagger UI.

Открыть в IDE именно эту папку `student`. Здесь свой Go-модуль. Требуется Go 1.22 или новее.

```bash
go mod download
go generate ./...
go test ./...
go run ./cmd/orders
```

Сервер слушает `127.0.0.1:8080`. Остановить его можно Ctrl+C. Если там уже запущено демонстрационное приложение преподавателя, сначала остановить его.

Работающие маршруты:

| Запрос | Результат |
|---|---|
| `GET /api/v1/status` | `200`, `{"status":"ok"}` |
| `POST /api/v1/orders` с `{"customer":"Алиса"}` | `201`, JSON заказа и заголовок `Location` |
| `GET /api/v1/orders/1` после создания | `200`, JSON заказа |
| `GET /api/v1/orders/abc` | `400`, `INVALID_ID` |
| `GET /api/v1/orders/999` | `404`, `ORDER_NOT_FOUND` |
| `GET /api/v1/orders` | `200`, JSON-массив заказов по возрастанию ID |
| `PATCH /api/v1/orders/{id}/status` с `{"status":"cancelled"}` | `200`, отменённый заказ; повторная отмена возвращает `409 ORDER_ALREADY_CANCELLED` |

У каждого заказа есть `id`, `customer`, `status`. При создании сервер присваивает `status: "new"`. Данные хранятся в памяти и исчезают после перезапуска. Повторные заказы одного клиента разрешены.

Тело POST должно содержать ровно один JSON-объект с полем `customer`, максимум 1024 байта. Требуется `Content-Type: application/json`; параметры вроде `charset=utf-8` допускаются. Пустое или пробельное имя, неизвестные поля, `null` и лишнее JSON-значение отвергаются. Ошибки API под `/api/v1/` имеют формат `{"error":"описание","code":"СТАБИЛЬНЫЙ_КОД"}`. Неизвестный маршрут возвращает `404 ROUTE_NOT_FOUND`, неподдерживаемый метод — `405 METHOD_NOT_ALLOWED` с заголовком `Allow`.

Основные файлы:

- `cmd/orders/main.go`: общие аннотации API.
- `internal/httpapi/handlers.go`: аннотации конкретных операций.
- `internal/httpapi/dto.go`: типы тела запроса и ответов.
- `internal/httpapi/routes.go`: маршруты и место для подключения UI.
- `generate.go`: команда генерации закреплённым `swag v1.16.6`.
- `requests.http`: запросы для ручной проверки.

Swagger UI: `http://127.0.0.1:8080/swagger/index.html`.
Спецификация: `http://127.0.0.1:8080/swagger/doc.json`.
Для обновления документации:

```bash
go generate ./...
```

Команда обновляет `docs/docs.go`, `docs/swagger.json` и `docs/swagger.yaml`. Генератор закреплён на версии `v1.16.6`.

## Список заказов

`limit` принимает значения от 1 до 100, по умолчанию 20. `offset` принимает
значения от 0, по умолчанию 0. Например, `/api/v1/orders?limit=1&offset=1`
возвращает второй заказ. Пустая страница возвращает `200` и `[]`.

Необязательный `status` принимает только `new` или `cancelled`.
Без него возвращаются все заказы. Сначала применяется фильтр, затем сортировка
и пагинация. Например, `/api/v1/orders?status=new&limit=1&offset=1`
возвращает второй заказ среди новых. Если отменённых заказов нет,
`/api/v1/orders?status=cancelled` возвращает `[]`. Пустой, неизвестный или
повторный `status` возвращает `400 INVALID_QUERY`.

В числах допустимы только десятичные цифры в пределах `int`. Пустые, повторные,
неизвестные параметры и неверные значения возвращают `400 INVALID_QUERY`.
Внутренняя ошибка возвращает `500 INTERNAL_ERROR`.

## Отмена заказа

`PATCH /api/v1/orders/1/status` с `Content-Type: application/json` и телом
`{"status":"cancelled"}` меняет статус только из `new` в `cancelled`.
Ответ `200` содержит обновлённый заказ. Повторная отмена возвращает
`409 ORDER_ALREADY_CANCELLED`, неизвестный заказ возвращает
`404 ORDER_NOT_FOUND`. Неверный ID возвращает `400 INVALID_ID`,
неверный JSON возвращает `400 INVALID_JSON`, неподходящий статус возвращает
`400 VALIDATION_ERROR`. Ограничения тела те же, что у создания: больше
1024 байт возвращает `413 BODY_TOO_LARGE`, неверный Content-Type возвращает
`415 UNSUPPORTED_MEDIA_TYPE`.

Проверка и изменение статуса выполняются под одной блокировкой хранилища.
При двух параллельных отменах один запрос получает `200`, другой получает `409`.

## Проверка

Из папки `HW7/student`:

```bash
go generate ./...
go test -race ./...
go vet ./...
go build ./...
```

HTTP-тесты проверяют создание и чтение, пустой список, страницы, сортировку,
значения по умолчанию, неверные параметры, максимальный допустимый `offset`,
фильтрацию до пагинации, отмену заказа, повторную и параллельную отмену.
