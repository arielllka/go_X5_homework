# Сервис заказов

Сервис создаёт заказы, показывает список и историю, позволяет менять статусы.
Данные хранятся в памяти и пропадают после перезапуска.

## Запуск приложения

Нужен Go 1.22 или новее. Команды выполняются из папки
`control/go-orders-current-control-starter`, рядом с `go.mod`.

```bash
go mod download
go run ./cmd/api
```

Сервер работает на порту 8080. Остановить его можно через Ctrl+C.
Другой адрес можно задать переменной `HTTP_ADDR`.

Проверка во втором терминале:

```bash
curl http://localhost:8080/health
curl -X POST http://localhost:8080/api/v1/orders \
  -H 'Content-Type: application/json' \
  -d '{"items":[{"name":"Book","quantity":2,"price":100}]}'
```

## Работа с заказами

Цена указана в копейках. Сумма заказа считается по цене и количеству каждой
позиции. У заказа должен быть хотя бы один товар. Название не должно быть пустым,
а количество и цена должны быть больше нуля.

ID заказа должен быть положительным целым числом. Некорректный ID возвращает
400, а положительный ID отсутствующего заказа — 404.

| Метод | Путь | Действие | Код успеха |
|---|---|---|---|
| GET | `/health` | Проверка сервера | 200 |
| POST | `/api/v1/orders` | Создание заказа | 201 |
| GET | `/api/v1/orders` | Список заказов | 200 |
| GET | `/api/v1/orders/{id}` | Получение заказа | 200 |
| PATCH | `/api/v1/orders/{id}/status` | Изменение статуса | 200 |
| GET | `/api/v1/orders/{id}/history` | История статусов | 200 |

Для изменения статуса передаётся JSON, например `{"status":"processing"}`.
Из `new` можно перейти в `processing` или `cancelled`, из `processing`
в `completed` или `cancelled`. Конечные статусы менять нельзя.

При создании устанавливается статус `new` и добавляется первая запись в историю.
Повторно установить текущий статус нельзя. История содержит статусы и время их
изменения и возвращается в хронологическом порядке.

## Ответы с ошибками

Ошибки возвращаются в JSON с полями `error` и `code`: 400 для неверных данных,
404 для отсутствующего заказа, 409 для запрещённого перехода, 500 для внутренней
ошибки. Например, для отсутствующего заказа:

```json
{
  "error": "order not found",
  "code": "ORDER_NOT_FOUND"
}
```

Внутренние ошибки записываются в лог, клиент получает общее сообщение.

## Устройство проекта

В `handler` находятся HTTP-обработчики, в `service` бизнес-логика,
в `repository/memory` хранилище. Типы и интерфейс репозитория описаны в `order`.
Зависимости передаются через конструкторы в `cmd/api/main.go`.

Обработчик разбирает JSON и ID из URL, вызывает сервис и возвращает HTTP-ответ.
Сервис проверяет данные заказа и положительный ID, считает сумму и управляет
статусами и историей. Репозиторий сохраняет и возвращает заказы.

Логи выводятся через `slog` в формате JSON и содержат `method`, `path`, `status`,
`duration`, `request_id`. ID запроса также передаётся в заголовке `X-Request-ID`.
Recovery middleware перехватывает панику и записывает её в лог. Если ответ ещё
не отправлен, клиент получает JSON с кодом 500.

## Тесты и проверка кода

```bash
go test ./...
go test ./internal/service/... -cover
go vet ./...
go build ./...
gofmt -l .
```

Покрытие сервиса при последней проверке: 100%. Тесты написаны на `testing`
и `testify/require`, используют таблицы сценариев и подмену репозитория. Проверяют
создание, валидацию, сумму, получение заказов, переходы статусов и историю.
Также проверяются нулевой и отрицательный ID при получении заказа, смене
статуса и чтении истории. После изменений покрытие можно измерить командой выше.
