# Сервис заказов

Самостоятельная работа после занятия 6: перенос однофайлового сервиса заказов
в несколько пакетов. Программа создаёт заказ для клиента «Покупатель» с ID `1`
и статусом `new`. Заказы хранятся в памяти текущего процесса, поэтому при новом
запуске нумерация снова начинается с `1`.

## Структура

```text
HW4/
    cmd/orders/main.go
    internal/
        config/config.go
        handler/handler.go
        model/order.go
        repository/memory.go
        service/service.go
    README.md
    go.mod
```

| Пакет | Назначение |
|---|---|
| `cmd/orders` | Точка входа: получает конфигурацию, создаёт хранилище, сервис и обработчик, выводит результат. |
| `internal/config` | Читает `HTTP_ADDR` и задаёт адрес по умолчанию `:8080`. |
| `internal/model` | Описывает `Order` с полями `ID`, `Customer`, `Status`. |
| `internal/repository` | Реализует `Memory`, сохранение заказа и поиск по ID. Для отсутствующего заказа возвращает `ErrNotFound`. |
| `internal/service` | Проверяет имя клиента, назначает ID и статус, сохраняет заказ через интерфейс `Repository` с методами `Save` и `ByID`. |
| `internal/handler` | Передаёт создание заказа зависимости через локальный интерфейс `Creator`, содержащий только метод `Create`. |

Конкретные объекты создаются в `main` и передаются через конструкторы.
`service` не импортирует `repository` или `handler`; `handler` не импортирует
конкретный сервис. Глобального хранилища нет. Пустое имя возвращает
`service.ErrEmptyCustomer`. При ошибке `Save` сервис возвращает ошибку и пустой
заказ, а следующий ID не увеличивается.

## Запуск

Нужен Go 1.22 или новее. Корень модуля `example.com/orders` — папка `HW4`.
Из корня репозитория:

```bash
cd HW4
go run ./cmd/orders
```

Ожидаемый вывод:

```text
сервис слушал бы :8080, создан заказ: {ID:1 Customer:Покупатель Status:new}
```

Программа демонстрирует сборку приложения и создание заказа. Сетевой порт
не открывается.

## Конфигурация

Адрес задаётся переменной окружения `HTTP_ADDR`. Если переменная не задана
или пуста, используется `:8080`. Конфигурация читается один раз при сборке
приложения в `main`.

В bash/zsh из папки `HW4`:

```bash
HTTP_ADDR=:9090 go run ./cmd/orders
```

В PowerShell из той же папки:

```powershell
$env:HTTP_ADDR = ":9090"
go run ./cmd/orders
Remove-Item Env:HTTP_ADDR
```

Ожидаемый вывод второго запуска:

```text
сервис слушал бы :9090, создан заказ: {ID:1 Customer:Покупатель Status:new}
```

## Проверка

Все команды выполняются из папки `HW4`:

```bash
gofmt -w .
go mod tidy
go list ./...
go build ./...
go vet ./...
gofmt -l .
```

`go list` должен показать точку входа и пять пакетов `internal`, сборка и
`go vet` должны завершиться без ошибок, `gofmt -l` не должен ничего выводить.
Проверьте оба запуска выше: меняется только адрес, данные заказа сохраняются.
Внешние библиотеки не используются, поэтому `go.sum` не требуется.
Автоматических тестов в этом задании нет: ответ `no test files` при
`go test ./...` не означает проверку бизнес-логики.
